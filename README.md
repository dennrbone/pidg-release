# PIDG

PIDG — шлюз проверки вызовов инструментов ИИ-агента. Он принимает запрос от агента, проверяет разрешения и аргументы и передаёт разрешённый вызов исполнителю. Соединение использует MCP, протокол обмена сообщениями между агентом и инструментами.

## Установка и первый запуск

Нужен Python версии 3.11 или новее. В терминале из корня репозитория выполните команды.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install .
pidg init --directory demo --atomic-contracts
pidg config validate demo/gateway.json
```

Команда `init` создаёт настройки в новой или пустой папке. Демонстрационный исполнитель читает локальные записи и сохраняет заметки и сообщения в `demo/mock-state.json`.

Для подключения к GigaCode с локальным сервером MCP сгенерируйте фрагмент настроек.

```sh
pidg config generate --target gigacode-bundled --gateway demo/gateway.json
```

Добавьте выведенный блок `mcp.pidg` в файл настроек проекта `.gigacode_vsc/gigacode.jsonc` и перезапустите подключение к инструментам. В чате агента можно написать «Прочитай публичную запись с идентификатором `public` и сообщи число в ней». Демонстрационная запись содержит число 42.

Клиент MCP может запускать шлюз напрямую командой `pidg serve --config demo/gateway.json`. Запросы и ответы передаются через стандартный ввод и вывод.

## Что задаёт пользователь

В чате пользователь формулирует задачу. Разрешения задаёт человек, который настраивает шлюз. Он может быть тем же пользователем.

| Файл | Назначение |
|---|---|
| `gateway.json` | Режим шлюза, настройки исполнителей и пути к остальным файлам. |
| `task.json` | Цель задания, список инструментов и точные наборы разрешённых аргументов. |
| `policy.json` | Разрешения на операции, ограничения данных и требования к подтверждению. |
| `registry.json` | Утверждённые описания инструментов, схемы аргументов и контрольные суммы. |

В строгом режиме набор аргументов для любого действия, кроме чтения, должен совпадать с одним из наборов в `bindings` в файле `task.json`. Регистр букв и пробелы внутри строк имеют значение.

### Сохранение заметки с согласованием

Демонстрационные настройки разрешают записать текст `approved synthetic note` в раздел `user-notes`. Попросите агента сохранить эту заметку. Первый вызов вернёт идентификатор согласования. В терминале можно посмотреть запрос.

```sh
pidg approval pending --store demo/approvals.sqlite
pidg approval inspect --store demo/approvals.sqlite ACTION_ID
```

Подставьте вместо `ACTION_ID` идентификатор вызова. Сохраните проверенные аргументы в `demo/arguments.json`.

```json
{
  "namespace": "user-notes",
  "content": "approved synthetic note"
}
```

Подтвердите вызов.

```sh
pidg approval grant --store demo/approvals.sqlite ACTION_ID \
  --arguments demo/arguments.json --yes
```

Агент должен повторить тот же вызов в текущем сеансе. Подтверждение используется один раз. Результат можно проверить в списке `notes` файла `demo/mock-state.json`. Журнал шлюза читается командой `pidg audit export --path demo/audit.jsonl`.

## Границы защиты

Шлюз контролирует операции, которые проходят через него. Для ограничения прямого доступа агента к файлам, сети и инструментам требуется изолированный запуск. Атомарная проверка контракта требует поддержки со стороны исполнителя. Переданные агенту результаты инструментов остаются недоверенными данными.
